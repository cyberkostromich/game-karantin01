# Карта: Хамовники / Лужники

> Конфиг: `data/map_luzhniki.json` · Пайплайн: `tools/osm_city/` · Координаты POI приблизительные — сверить по OSM при первой сборке.

## 1. Почему Москва, а не Лондон

Оба города одинаково хорошо покрыты OpenStreetMap, поэтому по трудоёмкости разницы нет — город в обоих случаях генерируется из OSM. Москва выигрывает по трём причинам:
1. **Идентичность.** Панельки, сталинки, Комсомольский проспект, метро — узнаваемо для аудитории и выделяет игру среди «американских» зомби-апокалипсисов.
2. **Готовый левел-дизайн.** Петля Москвы-реки вокруг Лужников даёт естественные узкие места (мосты), арена — крепость, Воробьёвы горы — высоту.
3. **Масштабируемость.** Тот же пайплайн собирает ВДНХ, Сити, Измайлово для следующих карт.

## 3. Зоны и их роль

| Зона | Роль в геймплее | Ресурсы | Угроза |
|---|---|---|---|
| Арена «Лужники» | Стартовая база, Штаб у южной трибуны, поле — площадка эвакуации | — | Ночные волны |
| Парк Лужников | Ближнее дерево, первая лесопилка | Дерево +++ | Низкая днём |
| Комсомольский проспект | Остовы машин (железо), главный маршрут орды на север | Железо +++ | Высокая |
| Хамовники (жилые кварталы) | Мирные в панельках и сталинках, Продуктовые, Аптеки | Еда, люди | Средняя |
| Новодевичий монастырь | Второй укреплённый пункт: 15 мирных, каменные стены. Захват расширяет зону стройки | Люди | Средняя |
| Нескучный сад | Много дерева, событие дня 3 (12 выживших) | Дерево +++ | Высокая (далеко) |
| Воробьёвы горы | Высота: +20% дальности снайперам, обзор всей поймы | — | Гнездо на метромосту |
| Станции метро ×3 | Гнёзда, спавн ходоков. Зачистка = очки и мораль | — | Очень высокая |
| Мосты | Узкие места: держать малыми силами, ставить стены | — | Направления волн |

## 4. Пайплайн OSM → игра

```
overpass_luzhniki.ql ──curl──► luzhniki.osm.json ──build_city.py──► assets/city/luzhniki/
                                                                      ├── chunks/chunk_X_Z.glb   (128×128 м)
                                                                      ├── ground.glb
                                                                      ├── navgrid.png            (2 м/пикс)
                                                                      ├── resources.json         (деревья, остовы, лут)
                                                                      ├── pois.json              (сценарные точки → метры)
                                                                      └── report.json
```

**Шаги (локально, с интернетом):**
```bash
cd tools/osm_city
pip install trimesh shapely mapbox_earcut numpy pillow
curl -s -X POST https://overpass-api.de/api/interpreter \
     --data-urlencode data@overpass_luzhniki.ql -o luzhniki.osm.json
python3 build_city.py --osm luzhniki.osm.json --map ../../data/map_luzhniki.json \
                      --out ../../assets/city/luzhniki --bbox mvp
```
Проверка без сети: `python3 make_test_sample.py sample.json && python3 build_city.py --osm sample.json --map ../../data/map_luzhniki.json --out /tmp/city_test`.

**Правила генерации:**
- Высота здания: `height` → иначе `building:levels × 3 м + 1` → иначе по типу (`apartments` = 9 эт., `yes` = 5 эт.).
- Цвет стен по этажности/материалу (кирпич, панель белая/бежевая, сталинский жёлтый), крыши — `ROOF_D`.
- Дороги — буфер линии по ширине класса (`primary` 16 м … `footway` 2.5 м). Тоннели пропускаются.
- Вода — `natural=water`, `waterway=riverbank`, мультиполигоны.
- Деревья: точки `natural=tree` + рассев в парках (плотность из `map_*.json`, прорежено ×0.25).
- Остовы машин: каждые ~80 м по дорогам `primary/secondary/tertiary`.
- Лут: `shop=supermarket|convenience` → Продуктовый, `amenity=pharmacy` → Аптека, `shop=car_repair`/`amenity=fuel` → Автосервис, `shop=hardware` → Стройрынок.

**Пост-обработка в движке:**
1. Чанки → `MeshInstance3D` с общим материалом палитры. Здания — статическая коллизия (box по AABB или convex).
2. `navgrid.png` → `Grid.gd` (проходимость и стоимость для flow-field; дорога = быстрее технике).
3. Навмеш для пехоты/мирных запекается по чанкам при загрузке, наши постройки — динамические obstacles.
4. `resources.json` → MultiMesh деревьев и остовов; каждый инстанс = ресурсный узел с запасом.
5. Здания с `in_bounds` POI из `pois.json` получают роль (арена = safe zone, монастырь = форт).

## 5. Ручные доработки после генерации (левел-дизайнер)

- [ ] Арена: заменить экструзию на кастомную модель чаши стадиона с одним входом (юг).
- [ ] Новодевичий: кастомные стены с башнями (из OSM придёт только контур).
- [ ] Метромост: убедиться, что проходим поверху (OSM `bridge=yes` + `layer`), станция — POI с гнездом.
- [ ] Расставить 3 направления спавна по краям (`spawn_edges`).
- [ ] Проверить, что от Штаба до каждого моста есть путь техники.
- [ ] Силуэт МГУ — отдельный «задник» за пределами bbox.

## 6. Масштаб и производительность

| Параметр | MVP (`bbox_mvp`) | Полный (`bbox_full`) |
|---|---|---|
| Размер | ~3.4 × 2.7 км | ~4.7 × 3.9 км |
| Зданий (оценка) | 1 500–2 500 | 3 000–5 000 |
| Чанков 128 м | ~560 | ~1 100 |
| navgrid | ~1 700 × 1 350 px | ~2 350 × 1 950 px |

Для MVP рекомендуется начать с `bbox_mvp`, а если тик не укладывается в бюджет — урезать до 2.5 × 2.5 км вокруг арены.
