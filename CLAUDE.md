# Правила проекта для ИИ-агента (Claude Code / Cursor) — КАРАНТИН: МОСКВА

Скопируй этот файл в корень Godot-проекта как `CLAUDE.md` (или `AGENTS.md` / `.cursorrules`).

## Что это
Кооперативная RTS-выживалка 1–4 игрока: армия против зомби в Москве (Лужники). Читай по порядку:
1. `docs/01_GDD.md` — правила игры. 2. `docs/02_tech_spec.md` — архитектура и стек. 3. `docs/08_roadmap_tasks.md` — задачи.
Справочно: `docs/03_balance.md` (сгенерирован), `04_map_moscow.md`, `05_art_bible.md`, `06_asset_list.md`, `07_ui_hud.md`.

## Стек (заморожен)
Godot 4.6.x stable · GDScript со статической типизацией · ENet host-authoritative · GUT для тестов · glTF-ассеты с одним материалом `palette`.
Не добавляй плагины, C#, сторонние фреймворки и не меняй стек без явной просьбы. Альтернативы — только предложением в чате.

## Жёсткие правила
1. **Никаких цифр баланса в коде.** Любое число геймдизайна — из `data/*.json` через `Config`. Нет ключа — добавь в JSON и упомяни в отчёте.
2. **Симуляция отдельно от представления.** `src/sim/` не создаёт и не трогает `Node3D`, не читает ввод, не знает про UI. Общение sim → UI только сигналами `Events`.
3. **Зомби — не узлы.** Только SoA в `ZombieSystem` + MultiMesh в `ZombieRenderer`.
4. **Сеть:** клиенты шлют только команды из контракта (tech spec §4.2). Любое изменение состояния — на хосте в тике. Никакого `randf()` в sim без сида `World.rng`.
5. **Координаты:** метры, XZ-плоскость, Y вверх, север = −Z. Модели смотрят в +Z (glTF).
6. **Имена узлов моделей** (`turret`, `barrel`, `rotor_main`, `arm_l`…) — контракт с арт-пайплайном, не переименовывать.
7. **Тесты:** каждая задача из `08_roadmap_tasks.md` с логикой sim сопровождается GUT-тестом. Запуск: `godot --headless -s addons/gut/gut_cmdln.gd`.
8. **Не делать** то, что в GDD §17 «Явно НЕ делаем в MVP».
9. Тексты интерфейса — на русском, через `tr()` с ключами (локализация позже).

## Конвенции
- Файлы `PascalCase.gd` для классов, `snake_case` для ресурсов и ассетов. `class_name` у всех систем.
- Сигналы — прошедшее время: `civilian_infected`, `wave_started`, `building_completed`.
- Функции < 50 строк, системы < 600 строк; больше — дроби.
- Комментарии — зачем, а не что. Ссылки на правило: `# GDD §8.2`.
- Одна задача = один коммит/PR с ID: `M1-4: flow-field sectors + wall detour test`.

## Как работать над задачей
1. Найди задачу в `08_roadmap_tasks.md`, перечитай связанные разделы GDD/tech spec.
2. Если в спеке дыра или противоречие — остановись и задай вопрос, не додумывай геймдизайн.
3. Реализуй → тест → `python3 tools/balance_report.py` (если трогал data/) → отметь чекбокс.
4. В отчёте: что сделано, что не сделано, какие ключи data/ добавлены, как проверить руками.

## Глоссарий
Мирный, рекрут, ведомый, заражённый (инкубация) ≠ зомби, орда/волна, гнездо, база, шум, доктрина, день — см. GDD §18. Использовать эти слова одинаково в коде (англ. эквиваленты: civilian, recruit, follower, infected, zombie, horde/wave, nest, base, noise, doctrine, day).
